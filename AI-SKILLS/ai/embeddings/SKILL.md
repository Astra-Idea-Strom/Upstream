# Embeddings: Vector Models, Similarity Metrics & pgvector Indexing

## 1. Core Embeddings Invariants

1. **Model Dimension Consistency**: Embedding vectors must always be generated by the exact same model that produced the indexed vectors. Never compare embeddings across different models or dimensions.
2. **Normalized Vectors for Cosine Similarity**: For normalized unit vectors (||v|| = 1), dot product is mathematically equivalent to cosine similarity and significantly faster to compute.
3. **Appropriate Vector Indexing (HNSW vs IVFFlat)**:
   - **HNSW (Hierarchical Navigable Small World)**: Higher recall, faster queries, higher memory consumption; best for real-time production.
   - **IVFFlat (Inverted File Flat)**: Lower memory footprint, requires building after data is loaded, faster build times.
4. **Batch Generation with Hash Caching**: Never re-embed unchanged text. Cache embeddings keyed by SHA-256 hash of normalized text chunks.

## 2. Key Implementation Patterns

### A. pgvector Schema & HNSW Indexing (PostgreSQL)
```sql
-- 1. Enable extension
CREATE EXTENSION IF NOT EXISTS vector;

-- 2. Create document chunks table with 1536-dimension embeddings
CREATE TABLE document_embeddings (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id UUID NOT NULL,
    chunk_index INT NOT NULL,
    content TEXT NOT NULL,
    content_hash CHAR(64) NOT NULL,
    embedding vector(1536) NOT NULL,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 3. Create HNSW index using Cosine Distance (<=> operator)
CREATE INDEX document_embeddings_hnsw_idx 
ON document_embeddings 
USING hnsw (embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);

-- 4. Nearest Neighbor Query
SELECT 
    id, 
    content, 
    1 - (embedding <=> $1::vector) AS similarity_score
FROM document_embeddings
WHERE 1 - (embedding <=> $1::vector) > 0.75
ORDER BY embedding <=> $1::vector
LIMIT 5;
```

### B. Python ChromaDB Client Integration
```python
import chromadb
from chromadb.utils import embedding_functions

# Initialize persistent Chroma client
client = chromadb.PersistentClient(path="./data/chroma")

openai_ef = embedding_functions.OpenAIEmbeddingFunction(
    model_name="text-embedding-3-small",
    api_key="sk-..."
)

collection = client.get_or_create_collection(
    name="knowledge_base",
    embedding_function=openai_ef,
    metadata={"hnsw:space": "cosine"}
)

# Insert documents
collection.add(
    documents=["First doc chunk...", "Second doc chunk..."],
    metadatas=[{"source": "faq.pdf"}, {"source": "manual.pdf"}],
    ids=["doc_1", "doc_2"]
)

# Query semantic similarity
results = collection.query(
    query_texts=["How do I reset my credentials?"],
    n_results=3
)
```

## 3. Anti-Patterns to Avoid

- **Querying Unindexed Vector Tables in Production**: Running `<=>` on tables with > 10,000 vectors without an HNSW index results in full table scans and high latency.
- **Comparing Raw Embeddings with Mismatched Preprocessing**: Lowercasing during indexing but preserving case during query generation can distort distance metrics depending on model tokenizer.
- **Re-Embedding Identical Strings Repeatedly**: Burning API credits and network latency by re-calculating embeddings without a hash cache layer.

---

## 4. Verification Checklist

- [ ] Vector database index uses HNSW with appropriate distance operator (`vector_cosine_ops`).
- [ ] Embedding dimension matches model specification (e.g. 1536 for `text-embedding-3-small`).
- [ ] SHA-256 hash cache prevents duplicate embedding API calls.
- [ ] Similarity threshold filters out low-confidence noise (< 0.7).

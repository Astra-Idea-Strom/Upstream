# SECURITY-POLICY.MD: Universal Engineering Security Policy

> **Scope**: Security governance for AI code generation, skill evaluation, dependency management, execution sandboxing, secrets protection, and AI/LLM safety.  
> **Standard**: Zero Trust, Principle of Least Privilege, OWASP Top 10 (2021/2025), OWASP API Security Top 10, OWASP Top 10 for LLM Applications.

---

## 1. External Skill Review & Vetting Policy

All skills sourced from external repositories, community registries, or third parties are considered **UNTRUSTED** until subjected to a rigorous 6-point audit:

1. **Source Reputation & Provenance**:
   - Verify maintainer identity, repository history, commit frequency, and license compatibility (MIT, Apache-2.0, BSD).
   - Reject unmaintained, anonymous, or obfuscated repositories.
2. **Metadata & Frontmatter Inspection**:
   - Verify YAML frontmatter conformance (`name`, `description`).
   - Audit description for prompt-injection hooks or manipulative system-prompt overrides.
3. **Executable Script & Command Audit**:
   - Inspect all files under `scripts/`.
   - **Zero Tolerance**: Any script containing obfuscated code, base64 payloads, network reverse-shells, unauthorized data exfiltration, or curl-to-bash pipelines is instantly blocked and reported.
4. **Tool Permission Boundaries**:
   - Verify that the skill requests only the minimum necessary tool access (e.g., Read, Write, Edit, Bash).
5. **Dependency Audit**:
   - Inspect package dependencies. Flag bloated or untrusted transitive packages.
6. **Isolation**:
   - Store third-party skills in an isolated quarantine directory until validated by `tools/skill-auditing`.

## 2. Code Generation & Software Security Policy

Every software artifact generated by the AI system must adhere to defense-in-depth principles:

### A. Injection & Data Handling
- **SQL Injection**: Always use parameterized queries or type-safe ORMs (Prisma, Drizzle, SQLAlchemy). Raw string concatenation in SQL is strictly prohibited.
- **XSS (Cross-Site Scripting)**: Enforce automatic escaping in UI templates. Sanitize any rich text inputs (e.g., DOMPurify). Prohibit dangerous innerHTML injection without cryptographic sanitization.
- **Path Traversal**: Validate and canonicalize all file paths (`path.resolve`, checking bounds against root directories). Disallow raw user inputs in file access calls.
- **Command Injection**: Prohibit raw shell execution with concatenated user strings. Use parameter arrays with `execFile` or subprocess APIs.

### B. Authentication & Session Security
- **Passwords**: Enforce modern salted password hashing (Argon2id or bcrypt with cost factor $\ge 12$). Never use MD5, SHA1, or unsalted SHA256.
- **Tokens & Cookies**: Store session tokens in `HttpOnly`, `Secure`, `SameSite=Lax/Strict` cookies. Never store sensitive session tokens in client-side `localStorage`.
- **JWT Hygiene**: Validate signature, issuer, audience, and expiration. Prohibit `none` algorithm.
- **Rate Limiting**: Apply IP- and user-based rate limiting on all authentication and resource-intensive endpoints.

### C. Secrets & Sensitive Data Management
- **Zero Committed Secrets**: Never commit API keys, database passwords, private certificates, or secrets to Git.
- **Environment Isolation**: Utilize `.env` and `.env.example` templates. Ensure `.env` is listed in `.gitignore`.
- **Credential Redaction**: In logs, transcripts, and error outputs, automatically mask credentials (e.g., `Bearer sk-...` $\rightarrow$ `Bearer [REDACTED]`).

### D. Network, CORS & Header Hardening
- **CORS**: Explicitly whitelist origins. Never use `Access-Control-Allow-Origin: *` in combination with `Allow-Credentials: true`.
- **Security Headers**: Enforce Content Security Policy (CSP), Strict-Transport-Security (HSTS), X-Content-Type-Options: nosniff, and X-Frame-Options: DENY.

## 3. Dependency & Supply Chain Security Policy

1. **Lockfile Integrity**: Always commit and respect lockfiles (`package-lock.json`, `pnpm-lock.yaml`, `poetry.lock`).
2. **Audit on Install**: Run `npm audit` or `pip-audit` when introducing or upgrading packages.
3. **Minimal Dependency Footprint**:
   - Never install a 5MB dependency for a 5-line utility (e.g., `left-pad`, `is-number`).
   - Prefer native platform APIs (Node.js `crypto`, Web Fetch API, modern ECMAScript helpers).
4. **Pinning**: Pin critical dependencies to exact or minor-range versions to prevent supply-chain drift.

## 4. AI & LLM Specific Security Policy

Modern applications integrating Large Language Models face unique adversarial attack vectors:

### A. Prompt Injection Defense
- **System / User Segregation**: Never concatenate untrusted user input directly into system instruction headers without clear boundary delimiters (e.g., `<user_data>...</user_data>`).
- **Indirect Injection Mitigation**: When retrieving external web pages, emails, or PDF documents, treat retrieved content as **untrusted data**, not executable instructions.
- **Instruction Priority**: System prompt instructions must explicitly forbid user inputs from overriding core operating constraints or security boundaries.

### B. Tool Abuse & SSRF Safeguards
- **Tool Parameter Validation**: Validate all arguments passed to tools against strict schemas before execution.
- **Egress Restrictions**: Restrict AI-invoked web browsing or webhook calls to safe external domains. Disallow calls to private IP ranges (`127.0.0.1`, `10.0.0.0/8`, `169.254.169.254` AWS metadata).
- **Human Confirmation for Consequential Tools**: Tools that alter external systems, delete databases, or send outbound communications must require explicit human sign-off.

### C. Privacy & Data Leakage
- **PII Redaction**: Strip personal identifiable information, customer emails, credit card numbers, and health records prior to forwarding payloads to third-party LLM APIs.
- **Model Training Safeguards**: Ensure API configurations explicitly opt out of third-party model training on user data.

## 5. Security Incident & Anomaly Escalation

If an unresolvable security vulnerability, active exploit, or compromised dependency is discovered:
1. **Halt deployment immediately**.
2. **Document the exact vector and CVE/CWE reference**.
3. **Notify the user with clear remediation steps**.
4. **Flag the skill or pattern in `tools/skill-discovery/NEEDS-HUMAN-REVIEW.md`**.
